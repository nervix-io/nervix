# NSPL command completion acceptance ledger

This ledger maps each acceptance case in the command completion specification to executable
evidence. The `@command_completion` group contains the focused response-ordering and recovery
scenarios added for this contract. Existing feature scenarios provide the broader connector,
streaming, placement, and lifecycle coverage.

| # | Acceptance case | Executable evidence |
| ---: | --- | --- |
| 1 | Upload completes before immediate follower use | `cluster/resource_describe.feature`: **Upload remains pending until every live node installs the resource** holds one replica before promotion, cancels the first waiter, resumes the same upload identity, creates a hash map, and immediately queries it through all three nodes. |
| 2 | Upload failures reach the caller | `cluster/resource_describe.feature`: **Resource bindings use only completed versions** fails an installed version before promotion, verifies the failed result includes assigned version 3, and rejects binding that version; **Uploading an unknown resource fails** covers admission failure. |
| 3 | Resource identity survives interrupted waiting | `cluster/resource_describe.feature`: **Upload remains pending until every live node installs the resource**, **Upload retry reports one assigned version**, and **Upload retry after leader change reports the assigned version** cover detached waiting, same-digest replay, digest conflict, and leader replacement. |
| 4 | Incomplete uploads do not invent content | `cluster/resource_describe.feature`: **An incomplete upload does not admit content or consume its identity** closes a short body, then completes version 1 with the same identity. |
| 5 | Definitions are immediately observable | `runtime/domain_creation.feature`: **A created stopped domain is immediately visible through every follower** and `cluster/resource_describe.feature`: **Created resource is visible before upload**; authentication feature coverage exercises newly created users through a new session. |
| 6 | Lookup initialization is part of creation | `cluster/resource_describe.feature`: **Upload remains pending until every live node installs the resource** immediately queries the new hash map through every node; `runtime/lookup.feature`: **Malformed lookup records fail hash map creation** verifies initialization failure reaches the creating command. |
| 7 | Runtime creation and alteration complete | `runtime/dynamic_junction_alter.feature`: **A dynamic route construction change is used by the next message**; `runtime/alter_junction.feature`: **A structural junction ALTER uses entity pause and flow resumes**; `runtime/alter_relay_full.feature`: **Changing a running relay schema uses domain pause**; `runtime/alter_running_domain.feature`: **ALTER clears affected materialized branches and preserves independent branches**. |
| 8 | Runtime removal completes | `runtime/relay_materialized_state_alter.feature`: **Dropping materialized state purges state without interrupting relay flow** and the DROP cases in `runtime/create_if_not_exists.feature` and `cluster/placement.feature` perform immediate observations against the resulting graph. |
| 9 | START waits for source readiness | `runtime/mqtt_ingestion.feature`: **MQTT start failures do not leave a silently stopped ingestor**; `runtime/syslog_support.feature`: **Syslog UDP listeners follow node lifecycle, leadership, and membership**; server-ingestor scheduling scenarios immediately use listeners on every node. |
| 10 | STOP waits for remote stopping | `runtime/http_ingestion.feature`: **HTTP endpoint stops routing while its domain is stopped and routes again after it restarts**; `runtime/domain.feature`: stopped domains reject external traffic; domain lifecycle unit tests cover the last running domain. |
| 11 | TLS activation is complete | `cluster/internal_tls.feature`: **Interconnect certificate authority rotates without restarting the cluster** and HTTPS session coverage; the native TLS resource-mount feature family opens new connections after configuration; `runtime/resource_version_bindings.feature`: **Pinned bindings keep their version through uploads, dynamic alterations and a cluster restart** opens HTTPS connections that verify the pinned VHOST certificate after creation, after a later upload and after a restart. |
| 12 | Transaction staging only validates | `runtime/nspl_transactions.feature`: **Transaction commands report planned quiescence and COMMIT reports only the executed aggregate**, **Queued statements are preflighted against the transaction prefix**, and **Queue admission errors retain earlier request outcomes**. |
| 13 | COMMIT waits beyond durable progress | `runtime/nspl_transactions.feature`: **COMMIT remains applying until its durable model effect is activated** and **Transactional START and STOP remain applying through activation**; `cluster/placement.feature`: **A transactional placement consolidation commits one gated schedule** covers pause release and handoff. |
| 14 | COMMIT failures remain failures | `runtime/nspl_transactions.feature`: **A failing resumed commit records the failing step and preserves its prefix**; `runtime/alter_running_domain.feature`: failed schedule publication preserves the active graph. |
| 15 | Recovery resumes application | `runtime/nspl_transactions.feature`: **A commit interrupted between steps is completed by the new leader** and **A failing resumed commit records the failing step and preserves its prefix** verify successor execution and retained outcomes. |
| 16 | Disconnection does not revert execution | `cluster/placement.feature`: **A disconnected standalone command resumes by execution reference**; `runtime/nspl_transactions.feature`: **Transactional START and STOP remain applying through activation** drops the committing transport and reconnects a waiter, while **A clean session close reverts its open transaction** covers idle cleanup. |
| 17 | Caller deadlines only detach | `cluster/placement.feature`: **A caller deadline detaches from standalone command execution** expires the caller while the entity gate is held, then resumes the same reference after release. |
| 18 | Readiness belongs to an incarnation | `cluster/relocate.feature`: **A destination restart after preparation aborts the ownership handoff** and **A relocated assignment survives reconciliation, a dynamic alteration and a restart**; `runtime/domain_clock_contract.feature`: **A joining or restarted node installs the current clock generation before execution**. |
| 19 | Membership changes preserve the guarantee | `cluster/resource_describe.feature`: **Uploaded resources converge after a node rejoins the cluster**; `cluster/server_ingestor_scheduling.feature` covers stop and rejoin for listeners; failover and rejoin features cover the effective availability policy. |
| 20 | Independent operations make progress | `runtime/nspl_transactions.feature`: **A held commit does not block a commit in another domain**; `runtime/interconnect_admission.feature`: **A waiting relay admission leaves another domain runnable**; the failed-resume transaction scenario supplies a same-domain semantic conflict. |
| 21 | Later unrelated revisions do not move the target | `cluster.rs` unit tests **runtime_revision_readiness_advances_monotonically** and **runtime_preparation_and_completion_advance_independently** verify later revisions satisfy a fixed target; resource and domain-isolation scenarios continuously publish independent state. |
| 22 | Transport stays active during a long command | `cluster/resource_describe.feature`: **Upload remains pending until every live node installs the resource** performs `SHOW CLUSTER STATUS` while held and **Large resource replication preserves control responsiveness**; `cluster/bounded_execution.feature` and blocking subscription scenarios cover management and delivery progress. |
| 23 | Node administration completes | `cluster/cordon_node.feature`, `cluster/drain_node.feature`, `cluster/drop_node.feature`, and `cluster/relocate.feature` immediately verify scheduling eligibility, activated destination ownership, and remaining membership after their commands return. |
| 24 | No-op and session commands complete their own effect | `runtime/alter_quiesce.feature`: **A no-op ALTER is dynamic even while the domain cannot drain**; `runtime/session_subscription_names.feature` covers immediate named subscription use, deletion, and recreation; model mutation unit tests cover `IF NOT EXISTS`. |
| 25 | Streaming remains asynchronous | `runtime/generator.feature`, `runtime/window_processor.feature`, and `cluster/narrow_schedule_activation.feature`: **REQUIRED WAIT retention on an unaffected reader survives another runtime node's move** verify that starting and changing a graph does not wait for invented branches, records, windows, or generator ticks. |

The focused group is run with:

```text
cargo test --features testing --test scenarios -- -t '@command_completion' --concurrency 1 --fail-fast
```

The repository gates are `just ratchet` and `just validate`. The relevant existing feature files
remain part of the normal scenario suite, so this ledger does not replace their ordinary coverage.
